# お散歩ビンゴ

散歩中に見つけたものをマークしてビンゴを目指すゲームです。

🌐 **プレイはこちら** → https://b-w-hiroki.github.io/osanpo-bingo/game.html

---

## できること

### 🙂 ひとりで遊ぶ

散歩に出かけて、5×5のビンゴボードのお題を探して遊ぶ基本モードです。

**遊び方の選択肢**
- **📷 写真で記録**：お題を見つけたらマスをタップ → 写真を撮ってマーク
- **✓ マークだけ**：タップするだけでマーク（写真なしで手軽に）

**ボードのカスタマイズ**
- **難易度5段階**：かんたん / ふつう / むずかしい / おに / ガチおに
- **フリー入力マス**：0〜24マス分、自分だけのオリジナルお題を設定できる（1件最大20文字）
- **作り直す**：ゲーム中でもお題をシャッフルして新しいボードに切り替えられる

---

### 👥 みんなで遊ぶ（通常グループモード）

同じ合言葉を共有してグループプレイができます。

**グループプレイの特徴**
- 合言葉を決めてゲームを作り、友達に共有（最大8文字・自動生成ボタンあり）
- 同じ合言葉 + 同じ難易度なら**同じお題プール**から出題される
- 各自のボードレイアウトはシャッフルで異なる（自分だけのシートで遊べる）
- 参加人数を設定できる

**遊び方のイメージ**：家族や友達でそれぞれスマホを持って散歩。同じお題を探しながら、先にビンゴを揃えた人が勝ち。

---

### ⚔️ バトルモード（陣取りビンゴ）

同じ合言葉で遊ぶプレイヤーが、マスを先着で取り合う競争モードです。

**バトルの仕組み**
- お題を見つけて**写真を撮ってアップロードした人がそのマスを取得**（先着1名限定）
- 他のプレイヤーが先に取ったマスはグレーになり取れない
- 自分が取ったマスは緑で表示
- Realtime 通知と2秒ごとの補助ポーリングで全員の取得状況を同期

**画面で見えるもの**
- ✓ マーク：自分が取ったマス数
- 🛡️ 相手取得：他のプレイヤーが取ったマス数

**遊び方のイメージ**：散歩しながら同じお題を奪い合う。先に写真を撮った人がそのマスをゲット。多くのマスを取りビンゴを揃えた人が勝ち。

---

### 📷 写真機能

- カメラで直接撮影、またはライブラリから選択
- アップロード前にプレビューして確認・撮り直しできる
- 写真は自動圧縮（最大800px）でストレージを節約
- 各マスに1枚保存、削除も可能
- 写真付きマスはボード上にサムネイル表示

---

### 🏁 結果・共有機能

ゲーム終了後にまとめ画面が表示されます。

- **結果カード**：日付・プレイ時間・ビンゴ数・マーク数を表示
- **グループ名入力**：「家族で散歩」「友達3人で」など記録できる（最大50文字）
- **画像保存**：結果画面をそのまま画像としてダウンロード
- **SNS共有**：テキストで結果をシェア（対応ブラウザではWebShare API使用）

---

### ⚙️ その他の機能

- **オフライン対応（PWA）**：一度開けばインターネットなしでも遊べる
- **自動保存**：LocalStorageで状態を保持。ブラウザを閉じても続きから再開できる
- **合言葉のコピー**：画面下の合言葉をタップするとクリップボードにコピー
- **キーボード操作対応**：Enter でマーク、P で写真、Tab で移動
- **エクスポート／インポート**：JSON形式でデータのバックアップ・復元が可能

## バトルモードのセットアップ

バトルモードは**設定なしでも遊べます**（同一端末内での動作）。  
端末間でリアルタイムに競い合いたい場合は Supabase の設定が必要です。

1. `battle-config.example.js` を `battle-config.js` にコピー
2. `battle-config.js` に Supabase の URL と anon key を入力
3. Supabase Anonymous Sign-Ins を有効化
4. `battle_cell_owners` をバックアップし、既存行の移行・廃棄方針を決める
5. 非本番環境で `supabase/battle_rls_policies.sql` を適用し、拒否テスト後に本番適用を別途承認する

```
テーブル: battle_rooms, battle_room_members, battle_cell_owners
主要カラム: room_code, topic_key, cell_index, owner_user_id, owner_uid, photo_data
UNIQUE制約: (room_code, topic_key)
```

`battle-config.js` の anon key は、Supabase の設計上「クライアントに公開されることを前提としたキー」であり、
`.gitignore` の対象外として意図的にコミットされています（誤って公開されているわけではありません）。
anon key 自体は利用者の本人性を保証しません。実際のアクセス制御は Anonymous Auth の `auth.uid()`、
ルーム参加者テーブル、RLS に依存します。`photo_data` は通常の SELECT 権限から除外し、参加者だけが個別RPCで取得します。

## 開発者向け

### ローカルで起動する

```bash
npx --yes serve -l 3000
```

ブラウザで `http://localhost:3000/game.html` を開く。

### ファイル構成

```
index.html          … ランディングページ
game.html           … ゲーム画面
topics.html         … お題図鑑（topics.js から自動生成・直接編集しない）
app.js              … ゲームロジック（OsanpoBingo クラス）
styles.css          … スタイル
topics.js           … お題一覧・難易度別選択ロジック（topics_list.csv から自動生成）
battle-config.js    … Supabase接続設定（anon key のみのためコミット対象）
battle-config.example.js … 設定ファイルのテンプレート
app-battle.js       … バトルモード関連メソッド抜粋（レビュー参照用）
assets/icons/       … お題アイコン（配信用に最適化済み・最大512px）
```

### npm スクリプト

```bash
npm run build-topics        # topics_list.csv → topics.js を再生成
npm run build-topics-page   # topics.js → topics.html を再生成
npm run optimize-icons      # assets/icons のPNGを配信用に最適化
npm run optimize-icons:dry  # 最適化せず削減量だけ確認
```

アイコンを追加したら `npm run optimize-icons` を通してからコミットする。
ボードは1枚につき25個のアイコンを読み込むため、1枚のサイズがそのまま初回表示の通信量になる。

### 技術スタック

- HTML5 / CSS3 / JavaScript (ES6+)
- PWA（Service Worker・Web App Manifest）
- Supabase REST API（バトルモードのみ・任意）

### ブラウザ対応

Chrome / Firefox / Safari / Edge

## 姉妹アプリの導線（birdman studio 共通）

LP のヘッダーの切り替えメニューとフッターのアイコンは、`sister-apps.js` の `APPS` から描画します。アプリを追加・変更するときは `APPS` に1行足し、同じファイルを4リポジトリ（otsukai / osanpo-bingo / gohan-tabeta / osaifu）にコピーして、各 Service Worker のキャッシュ番号を上げてください。表示中のアプリ自身は自動で一覧から外れ、件数が増えるとメニューは縦・フッターは横にスクロールします。
